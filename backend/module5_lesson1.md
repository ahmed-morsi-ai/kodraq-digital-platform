# هندسة التخزين المؤقت باستخدام Redis في FastAPI

## 1. ما هو الـ Caching أصلًا؟
تخيل أن لديك طلب API متكرر مثل GET /products/42 يستهلك قاعدة البيانات آلاف المرات في الثانية. الـ Cache هو نسخة مؤقتة وسريعة تُخزن فيها البيانات لتقليل الاعتماد المباشر على المصدر البطيء (PostgreSQL).

- **Database**: المصدر الحقيقي للحقيقة (Source of Truth).
- **Redis**: نسخة مؤقتة وسريعة (Fast temporary copy).

## 2. النمط الأساسي: Cache-Aside
النمط الأساسي الذي سنستخدمه هو **Cache-Aside (Lazy Loading)**:
1. البحث عن البيانات في Redis أولاً.
2. إذا وجدت (Cache Hit)، يتم إرجاعها فوراً.
3. إذا لم توجد (Cache Miss)، يتم جلبها من PostgreSQL، تخزينها في Redis مع TTL، ثم إرجاعها.

## 3. لماذا نستخدم TTL و Invalidation؟
- **TTL (Time To Live)**: لتحديد مدة صلاحية البيانات ومنع بقائها قديمة (Stale Data).
- **Cache Invalidation**: حذف المفتاح من Redis فوراً عند تحديث البيانات في قاعدة البيانات (Write) لضمان صحة البيانات.
